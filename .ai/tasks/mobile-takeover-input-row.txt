## Guarded fix/design

查证范围：移动端 `terminal.dart`、`RemoteTerminalBindingCoordinator`、`TerminalViewportController`、`RemoteTerminalOutputController`、`SelfDrawnTerminalView`；desktop host `terminal_buffer_window`/baseline viewport；headless agent baseline；相关 mobile renderer/viewport/binding tests；历史 `1076a184`。

复用结论：复用已有 `_requestTerminalViewportOwnerBaseline` → `subscribeSession` → host `viewportCols/viewportRows` → target `screenData` 链。现有链路只缺首次 measured resize 后的触发；不新增 wire 字段、不缓存第二份 screen、不改 host/agent。

owner 与 invariant：`HomeController` 协调当前 measured mobile viewport 与 baseline request；Rust router/self-drawn view 继续作为唯一 screen/render state。coordinator 记录实际发起请求携带的几何参数，HomeController 将其与当前有效 baseline target 比较；不读取可变 snapshot dimensions 作此判断。当前 interactive session 必须最终发布 target-sized baseline；旧请求在途时沿现有 pending path 等待完成再协调。

最小充分机制：在 owned resize 更新 viewport controller 的有效目标后，比较 coordinator 请求尺寸与 measured target；不匹配时调用现有 owner baseline refresh，即使 resize envelope 被 dedup 也执行。owner state 早于首次 layout 时不消耗 refresh；无 measured size 时 provider 返回 null，不将 host reported size 当成本机测量。baseline 完成时重新比较目标，旧请求不匹配则补取，匹配 keyframe 沿原行为清除 pending。键盘打开时继续使用既有 baseline rows 规则；不新增 timer、wire 字段或屏幕副本。

真实备选及排除：

- 在 wire payload 增加 screen cols/rows：可行但跨 desktop/headless/protocol/mobile 扩大契约；现有 subscribe 已携带 target dimensions，非最小修复。
- Rust router 保存并在 resize 重放旧 keyframe：不能恢复超出旧 screen 的 TUI 行，且会新增第二份 screen/keyframe 状态；不满足 host target rows invariant。
- 仅扩大 local screen 或调整 renderer bottom window：只能遮盖尺寸错误，不能恢复已被 status 覆盖的 cell；red test 仍失败。

命中影响：异步 baseline request 与 first measured resize 竞态；使用现有 request/backoff/active-request 状态，需保留 superseded refresh intent。未命中：持久化、迁移、公共 API、LAN route、agent session 生命周期、发布配置。

verification_only：真实设备/北真堂截图及完整断连窗口仍只作交付前观察，不作为本地测试门槛。out_of_scope：断线后 agent 自动恢复、LAN relay/direct 首次选择、同时掉线原因。
