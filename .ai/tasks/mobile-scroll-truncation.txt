# 诊断（已完成）

## 现象

描述：移动端某终端会话"失去焦点"后：底部输入行（TUI 的输入条）不再出现，向上/向下拖动既不滚动本地历史也不转发给应用；滚动历史看起来被截断。任一"刷新"（折叠屏开合一次，或该会话产生新输出）后恢复；再次失去焦点又复现。
频率：deterministic（本机 2/2 复现）
环境：Honor Magic V3（FCP-AN10）外屏 1060x2376，Android 16/API36；app 2.0.3-beta.9.sideload（release，不可 debuggable）；宿主 = 本机 Codux 桌面 app（不是 headless host）。

## 复现（本机实测）

方法：app 前台显示某终端 → HOME（或切走）→ 回到 app。
观测：
- 屏幕底部条带（y1600-2180）在健康态为 `» Ask Codex to do anything` + 状态行；复现后输入行消失，只剩旧转录行 + 状态行。
- 底部工具栏（esc/tab/ctrl/shft/alt）两态都在 ⇒ 用户说的"输入条"是 TUI 的输入行，不是 app 工具栏。
- 触摸有效（点终端能弹出键盘），但拖动 3 次（上/下各方向）画面逐像素不变；宿主日志无 `kind=terminal.input` ⇒ 拖动既未本地滚动也未转发。
- 恢复：`adb shell wm size 1060x2100` → `wm size reset`（等价开合屏）后输入行回来。
证据等级：A（真机像素 + 两侧日志）

## 边界

last-known-good：失焦前的渲染（约 2 分钟内，历史尚短）
first-wrong：`_recoverForegroundState()` → `_mountVisibleTerminal(reason: 'foreground')` 强制发起 baseline 重载
方法：宿主日志 `terminal_baseline_send … tail=true screen=true` 与 app 日志 `mount session=… reason=foreground cached=true` 同时刻对齐

## 根因（A 级因果链）

1. 失焦：app 释放视口（`terminal.viewport.release`，两侧日志 22:37:09/14）；宿主改由桌面持有，宿主栅格按持有者尺寸。
2. `terminal.dart::_handleTerminalViewportState` 中同步本地屏栅格的动作**位于 handed-away 早退之后**；
   旧注释明确写着"不采用新持有者的（更宽）栅格——会画乱" ⇒ 被接管期间本地屏停在手机行数。
3. 宿主按自己栅格推来的帧进不了更矮的本地屏：底部行被钳到末行并被其下方行覆盖
   ⇒ 只剩转录行、输入行消失，且本地滚动无法找回（行从未被存下）。
4. 恢复前台时 app 确实重拉了 baseline，但 keyframe 同样按宿主栅格绘制、同样被钳
   ⇒ "自动刷新无效"；屏幕停在旧内容直到 TUI 重绘（新输出）或真实 resize（开合屏 → SIGWINCH）。

探针证据（先于改码的两个一次性 example，已删除）：
- 同栅格下重放 + keyframe **能**正确修复画面（否定"重放 clobber"）；
- 热重连的 baseline **被应用**并生效（否定"去重守卫丢帧"）；
- 帧按更高栅格绘制、本地屏更矮时，底部行丢失，签名与真机逐字一致（确认机制）。

first-wrong condition：
`handedAway == true` 时 `resizeScreen(...)` 未执行（早退），本地屏行数 < 宿主栅格行数。

## 交叉验证（决定性）

用户目视：**桌面 Codux 窗口里该会话底部有输入行，只有手机没有**。
⇒ 宿主屏幕与其 keyframe 是好的；丢失发生在手机本地屏幕（行数落后于宿主栅格，帧与 keyframe 都被钳）。

## 已排除

- host 侧屏幕陈旧/被裁剪：桌面渲染有输入行，排除。
- "重放被裁剪历史 clobber 屏幕"：同栅格下 keyframe 能修复，探针否定。
- "恢复时的 baseline 被去重守卫丢弃"：探针显示 baseline 被应用且生效，否定。
- app 工具栏（esc/tab/ctrl…）消失：两态均在，排除。
- 拖动未被接收：点击可弹键盘，排除手势链路。
- 全局 pan/滚动位置错位：像素测量两态同一栅格布局，排除。
- 8 秒 `terminal.viewport.claim` 风暴：`home_controller.dart` 的 20s 租约 keepalive（设计如此），非缺陷。
- 宿主只改 screen 不改 PTY 的 resize 路径：`crates/codux-runtime-live/src/terminal_pty/session.rs:810` 是唯一
  `screen.resize`，与 `pty_control.resize` 同处 `resize_viewport`，排除。

## 并存机制（历史证据，现已不是待裁决项）

`git show fa50ce3b`：同一路径上曾记录"`_sentBySession` 去重缓存仍记着手机上次发出的尺寸，桌面趁我们是非活动
viewer 时重新加宽宿主后，纠正性 rebind resize 被抑制，导致 baseline 在桌面栅格上抓取"，该修复 `236b3e8b`
6 分钟后被 revert（无理由）。本次探针未复现"baseline 被抑制/丢弃"，但同属"宿主与手机栅格不一致"一族，
本次修复（被接管期间就镜像宿主栅格）同时覆盖该取向。
