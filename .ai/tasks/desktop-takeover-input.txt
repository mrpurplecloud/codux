一句话描述：移动端控制的远程项目被桌面端接管后，桌面端仍无法输入。

## 等级

grade：Guarded
依据：根因跨 hosted viewport ownership、异步 terminal stream、共享 baseline assembler / output sequence 与 desktop emulator publication；涉及共享 runtime trait 和多个现有调用点。
升级触发证据：未修改版本稳定复现；两个最小失败测试分别锁定 owner 转本机后未请求 baseline，以及 chunked baseline 与交错 live output 未原子收敛。

## Active Contract

state：locked

### 目标

移动端正在控制远程 Codex 等 TUI 终端时，桌面端接管成功后立即保持既有输入与 resize 能力，同时用 host authoritative baseline 原子收敛当前 screen；桌面输入可见地出现在同一 agent 会话。普通 shell 接管行为保持正常。

### 证据

未修改 `/Applications/Codux.app` 2.0.3-beta.10 对 beta.9 host 稳定复现：Codex pane 接管后桌面输入 `z` 无显示；同项目 shell pane 相同步骤立即显示。手机重新打开 Codex pane 可见该 `z`，而桌面再次接管仍不可见，证明输入已到 PTY，desktop current screen 未收敛。失败测试 `hosted_local_viewport_refresh_requests_current_screen_baseline` 实际仅记录 resize、缺少 baseline；失败测试 `requested_chunked_baseline_reconciles_before_interleaved_live_output` 显示较新的 `latest` 被后续 baseline history 覆盖为 `lateststale-tail`。根因证据 A。

### 授权变更

仅授权修复一个因果单元：desktop hosted-terminal consumer 的 authoritative baseline reconciliation。owner 转本机后保持既有交互权限，先 flush resize，再请求一次 tail baseline；共享 `RemoteTerminalOutputRouter` 负责 chunk assembly、sequence、baseline 期间 live hold 与取消时 live 恢复；完整 baseline 作为 replace 事件按同一 FIFO 交给 desktop emulator。不得增加 screen-publication readiness gate，不得修改 host 或 mobile 行为。

## 真实链

last-known-good：host authoritative current screen 已含桌面输入的 `z`；手机重新订阅同一 session 可见。
first-wrong：desktop 收到 owner=`remote:<desktop>` 后发布本机 owner 并解除接管态，但 `refresh_local_viewport_if_current_owner()` 仅 resize、不请求 current-screen baseline；即使 baseline 到达，`ControllerInner::route()` 逐 chunk 前送 raw history、在 history 非空时丢弃首 chunk `screenData`，且不处理 `outputSeq`，使后到 history 覆盖交错的新 live output。

## 根因

statement：desktop hosted terminal 绕过共享 remote-output reconciliation：本机 ownership transition 没有启动 baseline intent，controller 也把 baseline 当普通 byte chunks 并丢弃 authoritative `screenData`。因此 ownership 与 emulator publication可分离，TUI 接管后持续显示旧 screen。
first-wrong condition：本机 owner state 被接受时，`TerminalSessionBinding` 将 authority 视为可交互，但没有 pending/current-screen publication 状态，也没有调用已存在的 `terminal_buffer_tail()`；若 buffer 到达，`ControllerInner::route()` 在 `data` 非空时选择 raw data并忽略 `screenData`。
evidence_grade：A
evidence_reference：未修改设备复现；`cargo test -p codux hosted_local_viewport_refresh_requests_current_screen_baseline -- --nocapture` 失败，actual `['resize:terminal-1:100x30']`、expected 还含 `baseline:terminal-1`；`cargo test -p codux-runtime requested_chunked_baseline_reconciles_before_interleaved_live_output -- --nocapture` 失败，current screen 为 `lateststale-tail`。

# Fix

## Owner 与 invariant

owner：host-confirmed viewport owner 判定交互权限；`RemoteTerminalOutputRouter` 判定 inbound output 如何收敛；`TerminalModel` 应用已判定的原子替换。
invariant：本机 owner 到达即恢复既有交互；owner transition 只发起一次 baseline intent。chunked baseline 完整组装并吸收/排序交错 live output后，以 replace 事件进入同一 output FIFO；无独立 screen-ready/publication 状态。

## 选中修复

现成正确路径证据：移动端 `apps/mobile/lib/screens/home/state/terminal.dart` 在 owner 确认为本机后立即恢复交互，先 flush resize，再请求 owner baseline；chunk、sequence、held-live 与 gap 交给共享 `RemoteTerminalOutputRouter`，renderer直接读取 router snapshot，不等待 baseline publication。提交 `e969b00a`、`eb50bb85`、`7b822f12` 分别固定 handoff restore、atomic baseline restore 与单一 transport invariant owner。
机制：desktop 复用同一语义。在现有 runtime trait 暴露 `terminal_buffer_tail()`；本机 owner refresh 先发 resize，再以小型 `needs_owner_baseline` 协调位请求一次带 request id 的 baseline，不改变交互权限。`RemoteController` 仅在有限 baseline transaction 中启用共享 `RemoteTerminalOutputRouter`，普通 live 保持原 direct path；router生成 `Append` 或 `Replace { history, screen }`。desktop stream FIFO承载 append/replace；model replace 清空旧 emulator并恢复 history与 authoritative keyframe。请求发送失败时 router按 sequence恢复 held live，再由 controller在同一 output serialization lock 内投递 `Append`。
为何最小充分：复用 mobile owner/baseline时序、现有 host buffer wire contract、现有 shared router与 `HeadlessTerminalScreen` restore primitives；只新增 desktop 事件分层所需 intent 去重位和已有 stream 的 `Replace` 变体。删除 `screen_ready`、`baseline_pending`、`baseline_serial`、`HostedBaselinePublication`、snapshot generation gate及重复 `baseline_sessions`。
备选：host 在 Force 后主动推 keyframe，排除：需同时修改 desktop host与 headless agent，旧 beta.9 host不受益，并与 mobile现有 owner-baseline请求重复。只在 controller 首 chunk转发 `screenData`，排除：修复前交错测试证明后续 history可覆盖较新 live；会再造 shared router已有状态机。

## 实际风险

共享契约：`RuntimeTerminalStreamEvent`、`RuntimeTerminalController`；实际实现共 3 个（生产 `RemoteController`、生产 `WslRuntimeClient`、测试 `HostedTestController`），exhaustive match已枚举。WSL 无 hosted viewport identity，继续走默认 byte-stream，baseline 方法默认返回 false。
并发 / ownership：baseline chunks、live output与 viewport state异步交错；router持有并排序 live，controller在单个 output serialization lock 内投递 router结果。发送失败不得清空 held live。
兼容：legacy `register_terminal_output` adapter仍接收 bytes；unmanaged runtime默认 baseline method返回 false但不走 managed hosted readiness路径。
数据 / 持久化 / 安全：none。
回滚：纯代码，无迁移；回退上述文件即可。
verification_only：owner转移后即时 input/resize；resize-before-baseline；请求去重；multi-chunk首 chunk keyframe；baseline间交错live；send failure/cancel held-live恢复；Replace不丢更新的 UI resize intent；旧epoch；shell direct增量输出；所有 trait/event caller编译。
out_of_scope：host主动推 baseline、mobile router/UI、output ACK/gap主动重试、历史拥塞。
