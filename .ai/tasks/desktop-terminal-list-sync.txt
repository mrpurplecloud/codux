state：complete（2026-09-14；五项 Gate、target_check、nearest_regression_check、设备列表同步与桌面动态接管截图均通过；未 commit/tag/push，未要求移入 history）

### 目标

桌面控制端连接/重连并打开任一 remote host 项目后，左侧终端列表与 host 权威 running 终端集合收敛；其他客户端新建的终端会出现在桌面列表并可被桌面选中/接管；既有终端布局、顺序、本地持久化字段不被本地旧布局覆盖。不改变移动端和 host 的终端行为。

### 证据

- A 级复现：Honor 在 Mac Studio headless 的 VGBridge 项目新建终端 2（session `5ad693ff-b899-4c05-897f-c89cce5a4542`），手机终端列表显示 2 项；桌面打开同一远程项目时，`~/Library/Application Support/Codux/runtime-rust.log` 记录 `[terminal-restore] use runtime layout cache project=21a0a42a... top=1` 与 `[task-terminal-list] rows=1`；host 上该 session 为 running。
- first-wrong：桌面 controller 的项目目录同步只订阅 host 的 `projects` resource；对 remote project 没有订阅 `terminals` resource，也没有在项目已持久化时主动全量刷新 `terminal.list`。Host 的 `terminal.list` 基线/广播不会进入桌面布局 reconciliation，桌面只保留本地旧 layout。
- 因果链：手机 `terminal.create` → host 创建 running terminal 并广播/应答 `terminal.list` → 桌面未订阅 terminals 且打开项目时只读本地 layout → 桌面 `rows=1`。
- last-known-good：手机连接同一 host 时终端列表正确；桌面 runtime `apply_hosted_workspace_update` 已具备把 `terminal.list` 收敛到 `TerminalLayoutService` 的路径；host 的 project-scoped terminal subscription 已有实现与测试。

### 授权变更

仅新增 desktop controller 的 project-scoped `resource.subscribe`（`resource=terminals`、`baseline=true`，fire-and-forget），并在 remote project catalog 基线完成/目录变更后对当前 remote projections 调用；复用 host 现有 project terminal subscription 与现有 `terminal.list` apply/layout reconciliation。不新增 wire 类型，不修改 host/mobile，不新增客户端补偿机制。
