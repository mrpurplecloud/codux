升级触发证据：本任务即由 53a2ef74 的「控制器关闭 worktree 最后一个终端应拆掉桌面 split」契约未完整实现触发；新增测试在未修改版本失败。

## Active Contract

state：frozen

### 目标

控制器关闭某个 worktree 布局中的最后一个终端后，桌面端在同一作用域不再保留指向该已关闭会话的 split/终端；接管占位随之下线，点击接管不再出现无响应的死面板。普通多 pane 关闭、桌面本机关闭、移动端行为保持既有。

### 证据

复现（未修改版本，A）：新增测试 `apps/desktop/runtime/src/remote/host/tests/terminal_lifecycle.rs::remote_terminal_close_clears_layout_when_last_terminal_is_removed` 失败，输出 `persisted layout still lists the closed terminal: [TerminalPaneSummary { title: "Only", terminal_id: "terminal-only" }]`。该测试不 spawn PTY，绕开本沙箱 openpty 受限（`Operation not permitted`）的基础设施问题。

因果链：
1. 控制器 `terminal.close` → `RemoteHostRuntime::handle_terminal_close` 杀掉会话并调用 `remove_remote_terminal_from_layout`。
2. 该函数 load 布局、retain 掉 terminal_id；当这是布局中最后一个终端时 `after_total == 0`。
3. 它调用 `TerminalLayoutService::save_summary(key, 空布局)`；`sanitize_terminal_layout` 对空 `top_panes` 返回 `None`，`save_summary` 返回 `Err("Terminal layout is empty.")`，调用方 `let _ =` 丢弃 → 持久化布局仍是旧值（仍含已死 terminal_id）。
4. `publish_remote_terminal_layout_changed` 照常触发；desktop `reconcile_remote_terminal_layout` 重新 load 布局，`layout_ids` 仍含该死 id → 不删 pane。
5. 即使布局已空/缺失（controller 角色由 `apply_hosted_workspace_update` 正确 delete；或修好第 3 步后），`reconcile_remote_terminal_layout` 的 `while tab.panes.len() > 1` 也永不处理最后一个 pane → pane 仍滞留。
6. 滞留 pane 绑定已死会话：`local_viewport_owns()` 为 false → 渲染接管占位；点击接管走 `restore_local_viewport()` 对已死会话必然失败，只 `eprintln!`，UI 无反馈。

first-wrong：`remove_remote_terminal_from_layout` 在 `after_total == 0` 时用会拒绝空布局的 `save_summary` 持久化，并丢弃失败（host 角色）；以及 `reconcile_remote_terminal_layout` 的 `while tab.panes.len() > 1` 永不拆最后一个 pane（controller 角色及修好前者后仍阻塞）。

现有正确路径证据（Guarded 前置）：
- 同一收敛语义在 `apply_hosted_workspace_update`（desktop-as-controller）里已有正确路径：`after_total == 0` 时 `layout_service.delete(&layout_key)`，不走 `save_summary`。host 侧可复用同一 `delete`。
- 空布局/无布局在 `TerminalLayoutService::load` + `terminal_restore_plan_for_language` 已有正确路径：返回空 summary，restore 时生成默认终端。
- 已接受契约：commit `53a2ef74` 明确「a controller closing the LAST terminal of a worktree now tears down the desktop split too」，且 reconcile 注释写明「fall through and tear the now-stale desktop panes down instead of leaving an orphaned dead pane behind」。
- 既有测试 `remote_terminal_close_removes_layout_entry_and_kills_last_terminal` 当前断言 `layout.top_panes.len() == 1` 且仍是 session_a —— 它把 stale 行为写成了期望，修复时需一并更正为期望收敛。

证据等级：A（失败测试直读 persisted layout）+ B（reconcile guard 与 wire/代码路径）。

### 授权变更

只授权一个因果单元：让「控制器关闭 worktree 最后一个终端」在 host 持久化与 desktop pane 两端都收敛。最小改动为：
- host：`remove_remote_terminal_from_layout` 在 `after_total == 0` 时删除该 layout（复用已存在的 `TerminalLayoutService::delete`），不改 `save_summary`/`sanitize_terminal_layout` 的共享契约。
- desktop：`reconcile_remote_terminal_layout` 在布局不再包含某 pane 的 terminal_id 时，允许拆掉该 tab 的最后一个 pane（含空布局）；保持空 pane 列表可渲染的既有路径。
不新增机制、不改 protocol wire、不改移动端、不改 viewport 所有权语义。

### 现有正确路径证据

### 授权机制

causal_unit：控制器关闭 worktree 最后一个终端后的双端收敛。

1. host `remove_remote_terminal_from_layout` 在 `after_total == 0` 时改调既有 `TerminalLayoutService::delete`（非空仍 `save_summary`）。

# Diagnosis

## 现象与复现

环境：repo HEAD `e58b0b1e`（main），macOS；本沙箱 openpty 被拒（PTY 测试记 infrastructure）。
步骤：控制器对某 worktree 布局中唯一终端发 `terminal.close`；host kill 后检查持久化布局。
实际：持久化布局仍列出已关闭 terminal_id（新增 PTY-free 测试稳定失败）。
期望：持久化布局不再引用该 terminal；桌面同作用域 pane 随之拆除。
频率：always（当被关闭终端是该 layout 最后一个时）。
结果：failed
基础设施问题：PTY spawn 在本沙箱 `Operation not permitted`；已用不 spawn PTY 的测试绕过，非本 bug 因果。

## 真实链

last-known-good：commit `53a2ef74` 之前，host 在 `before_total <= 1` 直接 no-op，桌面 split 与 pad tab 都滞留（同样的问题，方向不同）。
first-wrong：`remove_remote_terminal_from_layout` 在 `after_total == 0` 时调用拒绝空布局的 `save_summary` 并丢弃错误。
因果链：见 Active Contract「证据」。
观察证据：失败测试输出；`TerminalLayoutService::save_summary` → `sanitize_terminal_layout` 空返回 None；`reconcile_remote_terminal_layout` 的 `while tab.panes.len() > 1`。

   discriminating_check：新增测试直读 persisted layout。

   result：host 侧独立复现，移动端发送与否非根因。

## 根因

statement：`53a2ef74` 引入的「关闭 worktree 最后一个终端 → 拆掉桌面 split」只改了一半：host 用会拒绝空布局的 `save_summary` 持久化空 summary（并丢弃 Err），desktop reconcile 又用 `while tab.panes.len() > 1` 保护最后一个 pane，导致持久化布局与桌面 pane 都不收敛，留下指向死会话的接管占位。
first-wrong condition：`after_total == 0` 且 `save_summary` 返回 Err 被忽略；以及布局 ids 为空时 `tab.panes.len() > 1` 为 false。
