### 证据

当前行为：用户报告 Worktree 侧栏关闭后状态未被记住，重启桌面 Codux 后再次显示，必须重新使用快捷键关闭。代码显示 `task_column_collapsed`、`project_column_collapsed`、`task_section_terminals_collapsed` 和 `task_section_sessions_collapsed` 只在 `CoduxApp` 内存中初始化 / 切换，没有持久化调用。现有正确路径：共享 `ConfigStore` 通过 `state.json` 承载项目状态，`update_raw_state_snapshot` 保留未知字段并由退出流程统一 flush；终端布局和文件编辑布局已有各自持久化实现。差距：主窗口侧栏折叠状态没有接入持久化路径。

### 授权变更

## Design Gate

查证范围与结果：
- `apps/desktop/src/app/window_actions/view_toggles.rs`：项目栏与 Worktree 栏切换函数是现有列可见性 owner；快捷键与 native menu 都调用它们。
- `apps/desktop/src/app/task_column.rs`：Terminals/Sessions 折叠点击直接修改同一 `CoduxApp` 状态字段。
- `apps/desktop/src/app/app_lifecycle.rs`、`apps/desktop/src/app/window_actions/windows.rs`：主窗口和辅助窗口构造都把四个字段硬编码为默认值。
- `apps/desktop/runtime/src/config.rs`、`project_store.rs`：`ConfigStore` / `update_raw_state_snapshot` 是 `state.json` 共享读改写 owner，保留未知字段、串行更新，退出由 `flush_all_config_writes` 落盘。
- `apps/desktop/runtime/src/project_store/terminal_layout.rs`、`terminal_layout.rs`、`file_editor_layout.rs`：已有布局持久化按不同语义分别复用 state/cache；没有主窗口侧栏折叠状态实现。
- 历史 `f1be6697`：终端 pane 折叠已按 worktree 接入 TerminalLayout；不覆盖主窗口侧栏可见性。

复用结论：复用共享 `ConfigStore` / `update_raw_state_snapshot` 和现有退出 flush；由 `RuntimeState` 加载可选 `uiLayout`，由 `RuntimeService` 提供写回入口，`CoduxApp.ui_layout` 持有运行时唯一布局状态。无需依赖、独立文件或新布局系统。

owner / invariant：`CoduxApp.ui_layout` 是运行时唯一 owner；`state.json.uiLayout` 是持久化投影。切换先更新 owner，再通过共享 state 更新投影；启动缺失 / 部分字段使用安全默认值。

选中设计：新增 `UiLayoutState`（四个带 serde 默认值的布尔字段）；`RuntimeState` 加载它；`RuntimeService::save_ui_layout` 只更新 `state.json` 的 `uiLayout` 字段；主窗口构造从 `RuntimeState` 初始化，四个现有切换点统一调用保存入口。

真实备选及排除：
- `settings.json` / `AppSettings`：排除。它承载用户偏好并映射 `SettingsSummary`，把瞬时主窗口布局放入此契约会扩大设置 API 和同步路径。
- 独立布局文件 / `PersistentCacheStore`：排除。当前全局项目 UI 状态已有 `state.json` owner，新增文件会重复持久化职责并增加恢复 / 备份路径。
- 按项目保存布局：排除。用户需求是桌面当前界面布局，现有四个状态也是 `CoduxApp` 全局字段，不存在项目键或项目切换语义。

接口、数据、兼容、迁移、回滚：只增加 `state.json` 可选顶层 `uiLayout`，旧文件无需迁移；缺失或部分值按现有默认恢复；raw 更新保留其他字段。无跨产品 API、依赖或数据库迁移。回滚代码后旧版本忽略 `uiLayout`；删除该字段即可恢复默认布局。

verification_only 风险：异步 state writer 在进程异常退出时可能尚未落盘；仅通过正常退出 flush 和持久化往返测试证明，崩溃恢复不在验收范围。

修改前方案审查：
1. 现有正确路径优先复用：通过；复用 `ConfigStore` / `state.json` / 退出 flush，无新增同职责存储。
2. owner / 机制解释需求：通过；当前硬编码初始化与无保存调用解释重启丢失，四个切换点接入持久化投影。
3. 语义范围：通过；只覆盖主窗口四个侧栏折叠状态，不扩展内容视图或其他产品。
4. 验证：通过；覆盖旧数据默认、往返落盘、四个状态、快捷键 / 菜单与桌面编译。
